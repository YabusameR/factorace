# factorace

ベルトコンベア搬送系の工業パズルゲーム。効率の良い工場レイアウトを設計し、目標生産数に到達するまでのタイムを競う。

## コンセプト

放置要素は薄めにし、「工場を組んで目標生産数達成までのタイムを競う」ことをコア体験に据えたパズル/タイムアタック型ゲーム。

## コアループ

1. ステージ(お題)ごとに「原料」「目標生産物・目標数」「利用可能な機械/搬送パーツ」が与えられる
2. プレイヤーはベルトコンベア+機械を配置して生産ラインを構築する
3. 稼働開始 → 目標数に到達するまでのタイムを計測
4. クリアタイムでランク付け、ベストタイム更新を狙う

## パズル性

- グリッドの広さ・搬送パーツの種類・機械の処理速度にトレードオフを持たせる(速いが場所を取る、安いが遅い、など)
- 評価軸を複数用意する(最短クリアタイム、最小パーツ数、最小スペースなど)
- 同じステージでもレイアウト次第でタイムが伸びる余地を残し、最適化のリプレイ性を確保する

## ランダム要素(特殊効果付きパーツ)

- ランダムで特殊効果が付いたレアパーツ(コンベア/機械/モジュール)をアンロック・ドロップさせ、既存パーツと入れ替えながら強化していく
- 例: 「搬送速度+20%だが幅が2マス必要」「加工時に確率で2倍産出」「隣接機械の効率を上げる」など
- 通常ステージとは別に「デイリーステージはランダムパーツ縛り」のようにモードを分ける案もあり

## スコープ(v1目標)

- 開発規模: 個人開発の小〜中規模(数ヶ月〜半年)
- ステージ数: 10〜15
- 機械種類: 5〜8種(搬送・分岐・合流・加工・貯蔵など)
- 特殊効果プール: 10〜20種からスタート、後で拡張しやすい設計にする
- タイムアタック用のリプレイ/ゴースト表示は後回し(まずはベストタイム記録のみ)

## 技術スタック

- エンジン: Godot

## ステータス

**ベース実装済み**(遊べる状態)。タイトル → ステージ選択 → 工場を組む → 稼働 → タイム計測 → ランク判定 →
ベストタイム保存、までひと通り動く。ステージ4本、パーツ8種。仕様は今後変更の可能性あり。

未着手/今後:リプレイ・ゴースト、ランダム特殊効果パーツ、デイリーステージ、ベルトの交差(立体交差)パーツ。

## 遊び方(操作)

| 操作 | 内容 |
| --- | --- |
| 左ドラッグ | 選択中のパーツを設置 |
| 右ドラッグ | 撤去 |
| `1`〜`9` | パーツ選択 |
| `R` | 向きを回転 |
| `X` | 撤去モード切り替え |
| `Space` | 稼働開始 / 一時停止 |
| `Esc` | ステージ選択へ戻る |

搬入口(緑)から原料が一定間隔で出てくる。コンベアと機械をつないで、搬出口(黄)へ目標のアイテムを目標数だけ
届けるまでのタイムを競う。稼働中もレイアウトは編集できるが、その時間もタイムに乗る。

## ゲームの仕組み

- **搬送**: コンベア1マスはアイテムを最大1個だけ持ち、`progress` が 1.0 に達したら次のマスへ渡す。
  渡せなければその場で待つ ⇒ これがそのまま詰まり(バックプレッシャー)になる
- **分配器**: 正面と、その右隣のマスへ交互に振り分ける。片方が詰まっていればもう片方へ逃がす
- **機械**: レシピ(入力アイテム → 出力アイテム、加工時間)を持つ。四方どこからでも素材を受け取り、
  矢印の向きへ完成品を出す。素材を混ぜた1本のベルトで供給すると詰まることがあるので、方向を分けて差し込むのがコツ
- **シミュレーション**: 1/60秒の固定ステップ。フレームレートに依らず同じレイアウトなら同じタイムになる

パーツやレシピは `game/src/core/defs.gd` の辞書に、ステージは `game/src/core/stages.gd` の配列に足すだけで増やせる。

## 構成

```
game/                       Godotプロジェクト本体
  project.godot
  main.tscn                 起動シーン(画面遷移のホスト)
  export_presets.cfg        Webエクスポート設定
  icon.svg
  scenes/
    title.tscn              タイトル
    stage_select.tscn       ステージ選択
    game.tscn               ゲーム画面
  src/
    app.gd                  画面遷移
    core/
      defs.gd               アイテム/パーツ(レシピ)の定義
      stages.gd             ステージ定義とランク基準タイム
      factory.gd            盤面と搬送/加工シミュレーション(描画非依存)
      save_data.gd          ベストタイムの保存(user://)
    ui/
      factory_view.gd       盤面の描画と設置/撤去入力
      game_screen.gd        ゲーム画面の制御
      stage_select.gd / title_screen.gd
  tools/
    headless_check.gd       エディタ無しでの動作確認(下記)
  assets/fonts/             日本語表示用のサブセットフォント(Noto Sans JP / OFL)
.github/workflows/
  deploy.yml                push時にheadless exportしてGitHub Pagesへ自動デプロイ
```

### 日本語フォントについて

Godot標準の埋め込みフォントは日本語グリフを持たないため、Noto Sans JP を使用文字だけに
サブセット化(約100KB)して同梱し、`project.godot` の `gui/theme/custom_font` で読み込んでいる。
UIに新しい漢字を足しても、かな・記号は全域を含めてあるので大抵はそのまま出る。
出ない文字が現れたらサブセットを作り直すこと(ライセンスは `game/assets/fonts/LICENSE-NotoSansJP.txt`)。

## 使い方

### 1. 手元で動かす

Godot 4.4 で `game/project.godot` を開いて実行する(F5)。CLIなら:

```bash
cd game
godot                      # エディタで開く
godot --headless --import  # 初回のみ。アセット取り込みとクラス一覧の生成
```

### 2. GitHub Pagesの設定(初回のみ)

対象リポジトリの Settings → Pages → Source を **"GitHub Actions"** に変更する。
(これをしないとワークフローがデプロイに失敗する)

### 3. ローカル/Claude Codeでの開発

`game/` 配下がGodotプロジェクト本体。GDScript(`.gd`)やシーン(`.tscn`)はすべてテキストファイルなので、Claude Codeで直接編集できる。

Godotエディタで開いて動作確認する場合は `game/project.godot` を開く。

エディタを開けない環境では、ヘッドレスの動作確認スクリプトを使う:

```bash
cd game
godot --headless --script res://tools/headless_check.gd
```

各ステージに想定解のレイアウトを組んでシミュレーションを回し、クリアできること・そのときのタイム・
獲得ランクを表示する。続けて全画面を生成して `_ready` / `_process` が例外なく回ることも確認する。
失敗があれば終了コード1。ステージの `par`(ランク基準タイム)を調整するときも、まずこれで実測する。

### 4. デプロイ

`main` ブランチにpushすると自動的に:
1. Godot(headless)でWebエクスポートを実行
2. `build/` の成果物をGitHub Pagesにデプロイ

デプロイ先URL: `https://<username>.github.io/<repo>/`

手動でワークフローを実行したい場合は Actions タブから `workflow_dispatch` で起動できる。

### 5. unityroomへの公開(節目リリース用)

GitHub Pagesは開発中の随時確認用。ある程度形になったら:
1. ローカル or CI成果物の `build/` フォルダをzip化
2. unityroomへ手動アップロード(Godot製ゲームのWebエクスポート、PCKファイル形式に対応)

## Godotバージョンについて

`.github/workflows/deploy.yml` の `GODOT_VERSION` を、実際に開発で使っているGodotのバージョンと合わせること。エディタのバージョンとエクスポートテンプレートのバージョンがずれるとビルドに失敗する。

## Web export時の注意

- `variant/thread_support` は既定でOFF(unityroomがThread Support未対応のため合わせてある)。マルチスレッドを使う場合は要検討
- 重いアセット/シェーダーはブラウザ性能に依存するので、UI中心のゲームから始めるのが無難
